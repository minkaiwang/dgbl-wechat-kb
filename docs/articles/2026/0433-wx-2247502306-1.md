▶ 摘要

对**非计算机专业**工科生而言，C/C++ 编程常被视为焦虑来源。本研究在土耳其 Marmara 大学电气电子工程系，以 **Octalysis 八核驱动**框架系统 redesign 2024–2025 学年入门编程课（BLM1005 C + BLM1030 C++/OOP），**N≈139+136** 人大班面授（土耳其语）。

游戏化要素包括：**Kahoot 周测**、透明成绩表、影视/游戏主题周、Hackerrank 挑战、连续奖励与 Persona 差异化激励。与往年未游戏化队列相比，**通过率由约 68% 升至 78%**（不及格 46→21 人）；双比例检验 **p=0.074**（趋势显著但未达 α=0.05）。问卷（n=91）显示 Kahoot、成绩追踪与实验课动机最高；Hackerrank 高竞争任务参与度低。学生实证动机权重与 ChatGPT 生成的 Octalysis 评分在 CD2/CD5/CD3 上高度一致。

▶ 任务目标

- ▶ **RQ1**：含公式与算法的编程课能否对非 CS 学生成功游戏化？
- ▶ **RQ2**：游戏化是否不仅提升参与，还能改善成绩与通过率？
- ▶ **RQ3**：哪些游戏化元素最有效？如何与 Persona/Octalysis 驱动匹配？

LV.01 介绍

编程学习难，对**非 CS 工科生**更难：习得性无助、师资不稳、语言选型不当、教学法忽视，叠加 LLM 时代「抄代码」对练习的挤压。游戏化（在非游戏场景使用排行榜、积分、连续奖励等）可提升重复任务的投入，但需避免「堆元素」——**Yu-kai Chou 的 Octalysis** 强调按动机驱动（白帽/黑帽、左脑/右脑）选人本设计。

既有研究多聚焦 CS 小样本或强依赖专用 App，较少在**大班非 CS 工程**中，用统一动机框架映射 Persona 与活动。本文在 139 人 C 语言 + 136 人 OOP 连续两学期课堂中实施，并与 2021–2024 非游戏化数据对照。

差异化：电气电子系、土耳其语面授、完整 C→C++→OOP 序列、Octalysis 驱动的 Persona×活动矩阵。

LV.02 文献综述

**编程游戏化脉络：**从自制学习游戏、移动端 OS 课程游戏化（Rey & Defensor, n=30）、Web 代码质量排行榜（Kasahara）、到 FGPE 欧洲平台——效果多为参与/成绩提升，但元素选择常缺理论依据。

**Octalysis 八核驱动（Table 2）：**史诗意义 CD1、进步 CD2、创意 CD3、拥有 CD4、社交 CD5、稀缺 CD6、好奇 CD7、损失规避 CD8。白帽驱动赋能，黑帽驱动紧迫；内在动机优于纯外在积分。

**本文定位：**Table 1 对比显示，少有研究同时覆盖非 CS、大班面授、双学期、Persona 与 Octalysis 显式映射。作者先在数字游戏设计系 2021–2024 课程中归纳四类学生画像，再迁移至 EEE 大班。

Flow 理论提醒：难度过高挫败，过低则无感——游戏化设计需在挑战与技能间找平衡。

★ LV.03 游戏设计 ★

Fig.1 Grand Kahoot 测验与报告界面

[图像 03：待版权审查，原图保存在私有归档]

**五阶段研究设计：**① 分析学生画像 → ② 按 Octalysis 为各 Persona 选元素 → ③ 两学期实施并监测 → ④ 收集成绩/迁移/问卷 → ⑤ 对照往年与 RQ 回答。

**Persona 划分（ProfileScore，式 1）：**0.45×学业成绩 + 0.30×过程（实验/项目）+ 0.25×出勤；按 cohort 百分位分档：

| Persona | 特征 | Octalysis 活动示例 |
| --- | --- | --- |
| P0 LEADER | 总分≥85，内在高标准 | Hackerrank 挑战、实验免修日、即时惊喜奖（CD3/7/1） |
| P1 BALANCED | 65–84，过程强、笔试弱 | 进度条式成绩表、补考测验、连续奖、低参与周倍数奖（CD2/8） |
| P2 STABLE | 测验/实验稳、笔试中等 | 周测、连续性奖、小组实验/项目、周主题、咖啡时间（CD1/5/4） |
| P3 STRUGGLING | <55 或出勤/作业不全 | 同级分组、保护盾（迟交/减罚）、周测、前 20 名小额奖、最快进步榜（CD8/2/3） |

**核心机制 1 · Kahoot（Fig.1）：**2024–2025 连续 **25 周**面授周测；场均约 10 题、约 70 人参与；年末 Grand Kahoot：**101 题、56 分钟、91 人、正确率 67%**。快答加分（黑帽时间压力）+ 前三名领奖台 + 连对榜。驱动 CD2 进步、CD5 社交。

**核心机制 2 · 透明成绩表：**周测加分、课堂即时奖、出勤、考试一并公示，充当「非正式进度条」，减少成绩申诉争议，强化 CD2。

**核心机制 3 · 周主题（Table 6）：**将抽象概念锚定影视/游戏——如 if/else →《黑客帝国》红蓝药丸；指针 →《盗梦空间》图腾；异常 →《阿波罗13》/《火星救援》危机管理。触及 CD1 史诗意义、CD7 好奇。

**其他：**Hackerrank 月度 C++ 排名挑战（面向 P0，参与偏低）；实验免修日、保护盾、即时课堂问答、咖啡时间、书籍/围巾等小奖（高频小额优于大额稀有奖）。

秋学期 BLM1005 末分配 Persona，春学期 BLM1030 追踪迁移——游戏化是**课程级系统**而非单一 App。

★ LV.04 方法和实验 ★

Fig.4 课程活动参与率

[图像 04：待版权审查，原图保存在私有归档]

**情境：**Marmara University EEE 一年级；2024–2025 秋 BLM1005（C，n=139）+ 春 BLM1030（C++/OOP，n=136）；土耳其语面授。对照组为 2022–2024 同课未游戏化队列（n≈145）。

**数据来源：**期中/期末/及格率、出勤；两学期 Persona 迁移矩阵；Kahoot/加分/实验参与记录；期末问卷（5 点李克特「动机程度」+ 强制单选「最 motivating 的一项」+ 理由子问卷）。问卷回收 **91 人（约 65%）**，90.1% 两学期均修读。

**分析：**描述统计；Persona 迁移频数；相对偏好权重 = 元素偏好率 × 理由偏好率，按 Octalysis 驱动累加；与 ChatGPT-5 独立 Octalysis 评分对照（Table 7）；通过率双比例 z 检验。

**透明度：**作者公开匿名化 Persona 规则、加分规则、问卷与聚合数据（见论文 Data Availability）。

局限：非随机对照（历史队列比较）；教师经验、评估标准、cohort 差异可能混淆；p=0.074 不能作严格因果断言；Hackerrank 与 LLM 使用未完全隔离。

**Persona 迁移（Fig.3）：**最大流 P1→P2（n=33）、P2→P2（n=28）——整体呈**稳定化**；P1→P0 改善 n=11；P1→P3 退步仅 n=2。游戏化主要巩固中等生，而非全员跃迁。

**参与与偏好（Fig.4–5，Fig.7）：**Kahoot 参与 **91%**，实验 **91%**，项目 **84%**。单选最 motivating：Kahoot 居首，主因「加分」。李克特最高：Kahoot、进度追踪、实验课；Hackerrank 最低。

**Octalysis 权重（Table 7，Fig.6）：**调查累积权重 CD2 **40.69**、CD5 33.02、CD3 27.49；ChatGPT 建议分 9/8/7——三者一致。CD6 稀缺驱动权重为 0；大额实物奖影响有限。

RQ 结论：编程课可游戏化；动机与成绩均有积极关联；**高频低门槛奖励 + 透明进度** 优于高难度竞技挑战。

LV.06 讨论与总结

讨论强调：Octalysis 的价值在于**先画像、再选驱动、再配活动**，而非照搬排行榜。对本公众号读者，此文是「无独立 3A 游戏」的**课堂级 DGBL**——Kahoot + 主题叙事 + 成绩可视化构成可复用套件。

与 Rahman VC3B（VR 化学）对比：同属 STEM 动机干预，但本文零头显、可扩展至百人大班；与 Onu 元宇宙综述对比：本文有**具体元素 A/B 偏好与历史队列成绩**。

作者诚实报告 p=0.074——在教育学现场研究中，这提醒读者：趋势 + 多源三角验证（成绩+迁移+问卷+Octalysis 对齐）有时比单一 p 值更能支撑教学决策。

未来：多学年 RCT、隔离 LLM 影响、将 Persona 算法工具化、向其他工科基础课复制。

★ 教学启示

■ 对教师

可从「周 Kahoot + 公开成绩表 + 周主题 5 分钟开场」三板斧起步；对非 CS 班少用高门槛 Hackerrank 式竞技，多用**人人可拿的周加分**。用 ProfileScore 找出 P3，优先给保护盾与小组互助，而非再加难度。

■ 对学校

大班编程课需制度支持：教师每周维护 Kahoot/成绩表的时间应计入工作量；统一加分规则减少申诉；土耳其语/英语界面需与校区 LMS 对齐。历史队列对比时，应固定考试难度或做等值化说明。

■ 对游戏设计师

设计非娱乐游戏化时：映射 Octalysis 驱动→机制→Persona；白帽（进步、创意）与黑帽（连击、限时）并用但避免操控感；主题叙事要**一眼对应知识点**（矩阵=分支，图腾=指针）。偏好权重公式可复用于迭代排优先级。

■ 研究者复现

复现：计算 ProfileScore 分 P0–P3；实施 Table 5 元素；记录 25 周 Kahoot 参与；对比前后学年通过率（双比例检验）；问卷含李克特 + 单选 + 理由→Octalysis 映射。公开数据见论文 repository。建议补充：效应量、按 Persona 分层成绩、LLM 使用调查。

💬 锐评

Software Quality Journal 发编程教学游戏化，对 DGBL 公众号是「**动机框架 + 大班实践**」型好文：比空泛元宇宙论文更落地，比纯 Kahoot 软文更有 Octalysis 与 Persona 矩阵。

亮点：139 人规模、双学期、与 ChatGPT Octalysis 评分的对照有趣；周主题表（矩阵/盗梦空间）可直接抄作业。不足：非严格实验；Hackerrank 失败经验值得读；p=0.074 被写进摘要却不宜过度宣传「显著」。

若你教公共课编程：**先 Kahoot 和成绩透明，再考虑 VR 化学教室**——这篇告诉你多数工科生要的是「看得见进步的小奖励」，不是少数人的算法排位赛。
